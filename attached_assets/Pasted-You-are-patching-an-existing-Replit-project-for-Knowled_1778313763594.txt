Step 2. Set up the data source with TWO modes (env-flagged so you can switch without code changes):

Mode A (default for production) — Live WordPress REST API:
- Endpoint: `https://knowledgeflowbooks.com/wp-json/wp/v2/book?per_page=100&_embed`
- Fetch at build time using `getStaticProps` / `generateStaticParams` (whatever this project uses)
- Cache for 1 hour (revalidate: 3600)
- Map WP fields to the Book type:
  - `title.rendered` → title
  - `slug` → slug
  - `excerpt.rendered` → excerpt (strip HTML)
  - `content.rendered` → description (sanitize HTML)
  - `_embedded["wp:featuredmedia"][0].source_url` → coverImage
  - Custom fields (ACF) for ISBN, ASIN, format URLs — map whatever exists
- Fallback gracefully if API is down: load from `data/books.json`

Mode B (fallback) — local JSON:
- File: `data/books.json`
- Same Book[] shape
- This will be regenerated from the Notion Title Metadata database export

Env flag: `BOOK_SOURCE` = `"wp"` | `"local"` — default `"wp"` in production, `"local"` in dev.
